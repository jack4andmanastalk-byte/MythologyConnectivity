## 0. エグゼクティブ・サマリー

本パッケージは **「実行でき、数値が再現し、報告書の転記精度が極めて高い」** という点で、プログラム成果物としては高水準にある。同梱された 4 本のスクリプト（v13 / v15 / v16 / v17）はいずれもエラーなく完走し、**CSV は全てバイト単位で一致**、PNG 図版も **MD5 完全一致** した。報告書の数値記載も、照合した **約 390 項目のうち、不一致は 12 項目（約 3%）にとどまり**、数値の捏造・転記ミスはほぼ見られない。

一方で、**「内容（結論）としての整合性」には重大な問題が 3 点** ある。

| 区分 | 判定 | 要点 |
| :--- | :---: | :--- |
| 実行可能性・再現性 | **A** | 全スクリプト完走、主要 CSV・図版はビット一致（HTML のみ §2.3 ①の 1 件が不一致） |
| データ構造の健全性 | **A** | 297 ノード / 597 エッジ、非巡回 DAG、重複・欠損・参照切れ 0 件 |
| 数値転記の正確性 | **A−** | 約 390 項目を照合し不一致 12 件（約 3%）。重大 2 件・軽微 10 件 |
| コード品質 | **B** | 6 件の実装上の欠陥（うち 2 件は出力の意味を損なう） |
| **方法論の妥当性（v17 第2層）** | **D** | **「85% 説明」は帰無仮説と区別できない（順列検定 p = 0.29）** |
| 方法論の妥当性（v5〜v16 第1層） | **B+** | **79.54% は帰無仮説を有意に上回る（p = 0.02）＝ 本体手法は支持される** |
| 文字種の健全性 | **A** | ハングル・デーヴァナーガリー・キリル文字 0 件、中国語専用漢字の混入 0 件 |

**最重要の指摘（3 点）**

1. **v17 の「厳密直交二層モデル」はネットワーク再計算ではなく、既存 2 結果の線形加重合成である。** `total = 0.7030 × (v16 の 75D 被説明率) + 0.2970 × (純 L2 の 15D 被説明率)` という四則演算に過ぎず、報告書が「3 段階アブレーション」「+20.57pt の改善」と呼ぶ数値は、**新しい証拠を一切含まない**。真の同時 90D 再計算（`joint_90d_simultaneous_ref`）では 54.23% → 68.58% → 70.24% であり、こちらは「参考」に格下げされている。
2. **第2層（15D）の「85.44% / 87.92% 説明」は、特徴量をノード間でランダムにシャッフルしても 81.15% ± 6.62% 出る。** 実測値の順位は 71.5 百分位、片側 p = 0.29 で **統計的に有意でない**。原因は次元の低さ（実効ランク 8.2）と疎性（109 本中 48 本が非ゼロ 2 次元のみ）、および「最大 3 親の貪欲減算」という評価関数の飽和性にある。**第2層に関する 6 大仮説の結論は、現状の指標では支持できない。**
3. **同一モデル内の重み規則の不整合により「固有核ランキング」が崩れる。** L2 プロファイルを持つ 30 話は重み 0.7030 で、持たない 7 話は重み 1.000 で計算されている。全 37 話を同一重みに統一すると、平均統合説明率は **82.17% → 77.27%**（v16 の 79.54% を下回る）に下がり、固有核上位は K2-09（50.2%）と K1-11（50.8%）のほぼ同率首位に変わる。**報告書の「TOP 5」は重み規則の副作用である。**

> 結論として、**Layer 1（v5〜v16 の 75 次元パイプライン）は「動く・再現する・統計的に意味がある」良質な基盤**であり、**v17 で追加された Layer 2 は「実装は正しいが、指標が結論を支えていない」** と評価する。したがって v17 の 6 大仮説の定量結論は「参考値」として扱い、主張の根拠にするには評価指標の再設計（後述 §5）が必要である。

### 2.3 コード上の欠陥（6 件）

#### ① 【中】v17 の HTML が再現せず、リテラル文字列 `nan` が 35 箇所混入する
`run_myth_v17_ritual_polity_layer.py:1016` ほかで `str(df_v16_n.loc[nid, "inherited_motifs"])` を実行しており、当該セルが NaN の場合に文字列 `"nan"` が生成される。v14 側の `pd.notna()` ガードは「文字列 `nan`」を非欠損と判定するため素通りし、アトラスのモチーフ欄に **`nan` がそのまま表示される**。同梱 HTML では当該 35 箇所が空文字になっており、**同梱 HTML は同梱スクリプトからは再現できない**（サイズも 408,994 B 対 409,099 B）。報告書の「408,977 B」はさらに別ビルドの値である。
**修正**: `... = "" if pd.isna(x) else str(x)` に置換。

#### ② 【中】`edge_type` の判定規則が歴史時代のノードで意味反転する
`396 行目`: `etype = "directed_transmission" if dt >= 350 else "shared_proto_or_parallel"`。
神話層では「350 年以上の隔たり＝直接伝播、近接＝共通祖型」という逆説的規則が成立し得るが、**律令ノード（701 年）→ 古事記（712 年）は dt = 11 年** であり、これを `shared_proto_or_parallel`（共通祖語・並行発生）とラベルするのは明らかに誤りである。実際 `LP16 → K2-09`（dt = 11）は shared_proto と記録されている。**597 エッジ中 204 本（34%）が dt < 350** で、このうち古事記流入が 42 本ある。
**修正**: `dt >= 350` ではなく「共通祖型の想定年代幅」と「史料成立年代」を分離した規則に改めるべき。

#### ③ 【中】`explained_frac` 列に 3 種類の異なる定義が混在
`v17_eurasia_297nodes_multiplex.csv` の同一列に、①既存 281 ノード＝v16 の 75D 剥離値、②LP01–LP16 ノード＝純 L2 の 15D 剥離値、③古事記 37 ノード＝直交合成値（`total_final_pct/100`）が混在している（`1003 行目`）。**互いに比較不能な量が 1 列に入っており**、HTML アトラスもこの列を色分けに使用している。利用者がノード間で説明率を比較すると誤読を招く。
**修正**: `explained_L1` / `explained_L2only` / `explained_composite` の 3 列に分離。

#### ④ 【中】ギリシャ起源ノードの除外がハードコードされている
`354 行目`: `if is_kojiki and sr == v15.GREECE_REG: continue`（v15・v16 にも同文言あり）。
v16 報告書 §4 は「エジプト＝古事記間の直接経路は形成せず、構造的類縁に留まる」と結論するが、**この結論は「ギリシャからの親を禁止する」実装によって一部は構成的に保証されている**。同様に `346 行目` で「古事記ノードは他ノードの親になれない」規則も暗黙の制約である。両者とも方法論的には妥当な選択だが、**報告書に明記されていない**ため、結論の独立性を過大評価させる。

#### ⑤ 【小】multiplex 生成時に L2 の大半のエッジを破棄している
`617 行目`: L2 エッジのうち「source/target が LP」または「target が古事記」以外を捨てている。したがって 597 本の multiplex は「L1 の 494 本＋L2 の一部 103 本」という**異種混成**であり、`L2_ext` 85 本のうち非 LP・非古事記エッジ（例 `MS01 → MS04`）は図に現れない。設計意図としては理解できるが、「90 次元空間の Multiplex DAG」という表現は実態より広い。

#### ⑥ 【小】`attach_stats` の位置代入
`out.loc[j, col] = st[j][col]` は index が `RangeIndex` である前提に依存しており、将来 `set_index` を挟むとサイレントに壊れる。`iloc` を使うべき。

### 2.4 意図的な設計だが注記が必要な点

- 貪欲剥離は **最大 3 親**（`for step in range(3)`）で打ち切られる。報告書に明記が無い。
- 有意性検定は **150 回の順列**で、達成可能な最小 p 値は 1/151 = 0.0066 である。「p = 0.0066」は下限値であり、実際には「p ≤ 0.0066」と読むべき。
- 古事記 37 話の `t_eff` は **全件 712（＝『古事記』成立年）** に統一されており、「神話の継承」ではなく「712 年時点で参照可能だったテクストの影響」を測るモデルになっている（§3.4 参照）。

### 3.3 方法論的検証（本レポートの中心）

以下は報告書の内部整合性ではなく、**指標そのものが結論を支え得るか**の検証である。パッケージの関数をそのまま流用し、追加の統制実験を行った。

#### (A) 「厳密直交二層モデル」はネットワーク再計算ではない

`compute_orthogonal_decomp()` の実装は次の 1 行に集約される。

```
total = w1 × (v16 の explained_frac) + w2 × (純 L2 の explained_frac)
```

剥離 DAG の再実行は一切行っていない。したがって：

- **Stage 0 = 60.81%** は「Layer 1 の実力」ではなく、**79.54% に 0.7030 を掛けただけ**の値である（30 話では 54.67%）。
- **Stage 0 → Stage 2 の「+21.36pt」は、w2 × (E_L2 − E_L1) という恒等式**であり、E_L2 > E_L1 である限り必ず正になる。仮に L2 の説明率が L1 より低ければ「悪化」として現れるが、それは L2 の証拠ではなく重みの算術である。
- **α 感度分析（0.50 / 0.65 / 1.00）も同様に恒等式**で、α を上げれば Stage 0 は下がり Stage 2 は上がるだけである。「序列と結論は頑健」は検証ではなく定義から自明。

報告書 §1 は「L1 の確定値 79.54% を破壊せず保持する厳密直交二層モデルを採用した」と述べるが、**同モデルの Stage 0 は 60.81%** であり、表示上は 79.54% を保持していない。「v16 のデータセットを改変しない」という意味なら正しいが、文面は誤読を招く。

**比較**: 真の同時 90D 再計算（`joint_90d_simultaneous_ref`）は 54.23% → 68.58% → 70.24% で、**L1 単独 54.23% は合成モデルの Stage 0（60.81%）より低い**。すなわち 90 次元空間での実際の剥離は、合成値ほど高く出ない。報告書はこれを「参考」に格下げしているが、**証拠としての優先順位は逆である**。

#### (B) 重み規則の不整合が「固有核ランキング」を決めている

`944 行目`: `w1 = w1_base if has_l2 else 1.0`。L2 プロファイルを持たない 7 話（K1-03, K1-08, K1-10, K1-11, K1-18, K1-19, K1-22）だけが **L1 を 100% の重みで計上**される。この規則の下では、L2 未付与の話が構造的に「残余が小さい＝固有性が低い」と評価される。

全 37 話を同一重み（0.7030 / 0.2970）に統一して再計算した結果：

| 指標 | 報告書の規則 | 全話同一重み |
| :--- | ---: | ---: |
| 平均統合説明率 | 82.17% | **77.27%**（v16 の 79.54% を下回る） |
| 固有核 1 位 | K2-09（50.16%） | **K1-11（50.79%）** |
| 固有核 2 位 | K1-17（36.96%） | K2-09（50.16%） |
| 固有核 3 位 | K1-15（33.57%） | K1-19（42.36%） |

**「K2-09 が不動の第 1 位」という中心的結論は、重み規則を変えると第 2 位に落ちる。** これは結論が指標設計に依存していることを意味する。

#### (C) 順列検定：第2層の「85% 説明」は偶然と区別できない

**手法**: ノードに付与された特徴ベクトルをノード間でランダムに並べ替え（時間・空間制約は保持）、同一の剥離エンジンで古事記 30 話の平均被説明率を再計算する。帰無仮説は「モチーフ・プロファイルとノードの対応関係は無情報」。

| 層 | 実測 | 帰無分布（並べ替え） | 片側 p | 判定 |
| :--- | ---: | :--- | ---: | :--- |
| **Layer 2（15D）** 親のみ並べ替え（n = 200） | 85.44% | 81.15% ± 6.62% | **0.289** | **有意でない**（71.5 百分位） |
| Layer 2（15D）全ノード並べ替え・地理制約なし（n = 20） | 85.44% | 94.15% ± 1.58% | — | 帰無の方が高い |
| **Layer 1（75D）** 全ノード並べ替え（n = 50） | **79.54%** | 64.04% ± 4.19% | **0.020** | **有意（5% 水準）** |

（Layer 1 の追試は v17 のエンジンで実行し、v16 公式値 79.54% を小数第 2 位まで再現した。エンジン間の等価性も確認済み。）

**解釈**:
- **Layer 1 は本物である。** 実測 79.54% は帰無分布の 3.7 標準偏差上にあり、motif プロファイルとノードの対応に実質的な情報がある。
- **Layer 2 は情報を持っていない。** 85.44% は「どのノードにどのベクトルを置いても 81% 前後出る」指標であり、K2-09 が 60.3%、K1-05 が 47.4% といった**個別値の差も、大半がベクトルの疎性（非ゼロ次元数）の差で説明できる**。
- 原因の定量: 109 本の L2 ベクトルのうち **48 本が非ゼロ 2 次元のみ**、PCA の第 1 主成分で 22.7%、**実効ランク 8.23**。15 次元・最大 3 親の貪欲減算では、ほぼどのベクトルも 3 手で 80% 以上に減算できてしまう。

**補足**: 有意性検定（`best_p`）でも同じ傾向が出ている。古事記 30 話のうち p < 0.05 は **5 話のみ**（中央値 p = 0.162）。しかも **K1-13 は被説明率 99.96% で p = 0.060、K2-05 は 98.36% で p = 0.053** であり、「ほぼ完全に説明できた」と「偶然と区別できない」が同時に成立している。これは**指標が飽和していることの直接証拠**である。報告書は 85.44% を強調する一方、この 5/30 という数字に言及していない。

#### (D) 二重計上の問題

L1 と L2 の被説明率は、**同一のターゲットベクトル・同一の親候補集合に対して独立に測定**されている。両者を加重和すると、L1 が既に説明した部分を L2 が再び説明した分も加算される。真の「L2 の増分寄与」を測るには、**L1 剥離後の残余ベクトルに対して L2 剥離を実行**する必要があるが、その実装は無い。したがって §3.3(A) の合成値は、原理的に「増分」を表していない。

#### (E) 6 大仮説テーマ表は L2 スコアの言い換え

§3 の表の「総残余削減率」は `(r0 − r2) / r0`（r0 = 100 − w1·E1）であり、**E1 がほぼ一定なので、順位は純 L2 説明率の逆順にほぼ一致する**（⑤ U29: 純 L2 89.3% → 削減 61.2% で最大、② M13: 75.2% → 48.4% で最小）。すなわち 6 大仮説の「識別的分離」は、**独立した 6 つの発見ではなく 1 つの指標の順位付け**である。また各テーマの話群は手作業で選定され（5〜11 話）、重複があり（K2-09 は 3 テーマ、K1-05 は 3 テーマに登場）、多重比較補正も信頼区間も無い。

#### (F) 時空間モデルの解釈上の制約

古事記 37 話の `t_eff` は全件 712 である。したがって「LP16（701 年）→ K2-09（神功皇后）」というエッジは、**「701 年の律令が 4 世紀の出来事に影響した」ではなく「701 年の制度語彙が 712 年の叙述に影響した」** を意味する。報告書 §4 の「天武・大宝令イデオロギーが中巻の歴史物語を逆照射・創出した」という解釈は後者としては妥当だが、**前者として読まれる危険がある**。この設定は報告書に明記されていない。

また、古事記流入 42 本（全体では 204 本）のエッジが「共通祖型」とラベルされる点（§2.3 ②）も、歴史時代の史料解釈としては再考を要する。

### 3.4 学術的事実関係の留意点（要確認事項）

いずれも結論を左右しないが、専門家の査読で指摘され得る点である。

1. **LP10「合部金光明経（570 年・北周）」**: 『合部金光明経』は隋代（597 年・宝貴編）の集成とされ、570 年という年代・北周という帰属は再確認を要する。

## 7. 付記：類似度判定の実装実態（LLM・Decision モデルの有無）

「もともと LLM／Decision API で類似度を判定させる設計だったものが、実態はハードコーディングになっているのではないか」という論点について、コードベースから確認した結果を記す。

### 7.1 LLM・外部 API は一切存在しない

- `openai` / `anthropic` / `requests` / `urllib` / `httpx` / `socket` 等の呼び出しは **全 11 スクリプトで 0 件**。ネットワーク通信は皆無。
- 埋め込みベクトル・学習済みモデルの読み込み・プロンプト定義も **存在しない**。
- v16 / v17 は `numpy` / `pandas` / `matplotlib` のみを直接利用し、**機械学習ライブラリを import していない**（`scikit-learn` が `requirements.txt` にあるのは、v5 `run_myth_analysis.py` がモジュール読み込み時に import するためで、v16/v17 は v5 の `WORLD_MYTHS` / `KOJIKI_EPISODES` / `MOTIFS` というデータ表しか使っていない）。

### 7.2 「判断」は人手、「計算」は本物

| 層 | 実装 | 性質 |
| :--- | :--- | :--- |
| **どの神話にどのモチーフがどれくらいあるか** | Python ソース内の辞書リテラル（手書き） | **100% ハードコード** |
| 類似度（dot 値・コサイン） | 手書きベクトル同士の内積 | 決定論的な算術 |
| 親の選択 | 貪欲剥離＋しきい値判定 | アルゴリズム（ただししきい値は手書き） |
| 有意性 | 順列検定 | 統計計算（本物） |

手書き入力の実量を数えると次のとおりである。

| 行列 | セル数 | 非ゼロ（＝人間が記入した値） | 1 ノード平均 |
| :--- | ---: | ---: | ---: |
| Layer 1（281 × 75D） | 21,075 | **1,500** | 5.3 |
| Layer 2（297 × 15D） | 4,455 | **322** | 1.1（L2 保有 109 ノードでは 3.0） |

加えて、更新辞書（`V16_WORLD_UPDATES` 37 ノード / 46 値、`V16_KOJIKI_UPDATES` 9 / 10、`L2_WORLD_UPDATES` 63 / 156、`L2_KOJIKI_UPDATES` 30 / 105）、変換ペア 42 本（75D）・52 本（90D）の重み、`score_thresh=0.45` / `dot_thresh=0.25` / `dt>=350` / 回廊距離 1,600・4,800・3,800・6,400 km もすべて手書きの定数である。

**すなわち「LLM が判断していた」構造は存在せず、判断を担っていたのは人間の手作業（アノテーション）である。** その意味でご懸念は正確である。

### 7.3 「Decision モデル」は v5 にのみ実在し、v13 以降は未使用

v5 `run_myth_analysis.py` には `DecisionTreeClassifier` / `RandomForestClassifier` / `LogisticRegression`（OvR 確率行列）／TOPSIS が実装され、`kojiki_ovr_decision_prob_matrix.csv` や `decision_tree_rules_*.txt` を出力する。ただし、

- 入力 `X` は **手書きモチーフベクトル**（`make_vec(w[6])`）、ラベル `y` は **人間が付けた文化圏名** であり、「Decision モデル」は手作業ラベルを再現する浅い分類器である。
- この分類器は v6 以降のパイプラインから **一度も呼ばれていない**（v16・v17 は v5 のデータ表のみ参照）。

したがって「Decision モデルによる類似度判定」は、少なくとも現行 v17 には実装されていない。

### 7.4 しきい値依存性（追加検証）

「類似度」の判定境界である 2 定数（`score_thresh` / `dot_thresh`）を動かすと、第2層の古事記 30 話平均被説明率は次のように変動する。<!-- doc-number-exempt -->

| score / dot しきい値 | 平均被説明率 | エッジ数 |
| :--- | ---: | ---: |
| 0.30 / 0.10 | 87.83% | 234 |
| 0.40 / 0.20 | 87.53% | 204 |
| **0.45 / 0.25（既定値）** | **85.44%** | **178** |
| 0.50 / 0.30 | 82.60% | 162 |
| 0.55 / 0.35 | 79.15% | 142 |
| 0.60 / 0.40 | 71.96% | 128 |
| 0.70 / 0.50 | 59.48% | 97 |

**28 ポイント幅で動く。** 「85.44%」は手書き入力と手書きしきい値の関数であり、しきい値の根拠・感度分析は報告書に一切記載がない。これは §3.3(C) の順列検定の結果（L2 は帰無と区別できない）と整合する。

### 7.5 ただし「手作業コーディング」自体は正当な手法である

比較神話学の標準的手法（スティス・トンプソンのモチーフ索引、ベレズキンの分布図法など）はいずれも人手のコーディングに依拠しており、手作業であること自体は欠陥ではない。問題は次の 3 点に集約される。

1. **コーディングの独立性・再現性が検証されていない**（単独者・ブラインドなし・κ 係数なし・コードブックの公開なし）。
2. **v17 では K 側と LP 側を同一人物が書いている**ため、対応関係が「設計したとおりに出る」構造になっている（例：K1-05 に R04 0.95 / R11 0.90 / R12 0.75 を与え、LP15・LP16 にも同種の値を与えている）。
3. **LLM／API による自動判定を名乗っていない**一方で、報告書も「人手によるアノテーション」と明記していないため、読み手が自動判定と誤解する余地がある。

**改善の方向**（§5 の 1〜4 と併せて）：LLM を使うなら「類似度を直接聞く」のではなく、**(神話, モチーフ) のセル値を原典引用付きで独立に付与させ、既存の人手値との一致率（Cohen's κ）で検証する** のが妥当である。仮説やアンカーを見せないブラインド設計、複数モデル・複数シードの合議、そして既存の順列検定による判別力の再評価を組み合わせれば、現在の枠組みをそのまま活かせる。
