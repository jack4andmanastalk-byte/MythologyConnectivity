# 表示混成 21 話の扱い（注記＋機械的出所台帳による運用）

対象: v17 インタラクティブ HTML 埋め込みグラフ（297 ノード / 597 エッジ）
日付: 2026-11-27
状態: 採用（ADR 0003）
関連: ADR 0001（リポジトリをハーネスとする運用）、`docs/prereg/20261127-display-mix-policy.md`

---

## 0. 結論

**凍結された v17 インタラクティブ HTML（`vendor/` 内）の図表示側は書き換えず、
「注記＋機械的出所台帳（`derived/` および CI 検証）」によって運用する。**

単なる文章注記は読み飛ばされる危険があるが、リポジトリ内で追跡可能な出所・乖離台帳
（`derived/html_embedded_v17_audit.json`）を保持し、`src/verify_network.py` が毎回
v17 実データから再計算した値と照合することで、「混成を隠さず、誤読を機械的に防ぐ」運用を成立させる。

---

## 1. 選択肢の比較

| 方針 | 利点 | 欠点・リスク |
| :--- | :--- | :--- |
| **A. HTML の表示側を直接修正する** | 画面上の数値と表示エッジが一致する | ① 凍結対象の `vendor/` を改変することになり v17 の原本証跡が失われる<br>② `.gitignore` で `*.html` と `vendor/` は追跡対象外のため変更履歴が残らない<br>③ 古事記の「82.17% / 85.44%」という主張が由来した歴史的計算（3 層分解）自体が見えなくなる |
| **B. 凍結 HTML は維持し、注記＋機械台帳で運用する（採用）** | ① 凍結原本 `vendor/` を不変に保てる<br>② `derived/` の JSON として git で差分追跡・査読ができる<br>③ 21 話の乖離を隠蔽せず、CI が毎回 100% 検出・出力する | v17 HTML 単体を注記なしで開いた読者には混成が見えない（対外配布時は注記を必ず添付する必要がある） |

---

## 2. 運用仕様（実装への落とし込み）

1. **原本の不変性**: `vendor/kojiki_mythology_v17_local/` 配下の HTML・CSV・スクリプトは一切改変しない。
2. **追跡可能な抽出台帳（ADR 0001 §4 準拠）**:
   * `derived/html_embedded_v17_audit.json` をリポジトリ管理下に置き、297 ノードそれぞれの
     出所（`v16.L1`: 244 / `decomp.total_final`: 37 / `pureL2_dom`: 16）と、
     表示値と L1 表示エッジ再計算値が 0.01 超ずれる全 21 話（すべて古事記）の個別差分・仕様注記を記録する。
3. **CI による自動検証**:
   * `src/verify_network.py` は、`vendor/` から再計算した 297 ノードの出所内訳および 21 話の乖離一覧が
     `derived/html_embedded_v17_audit.json` の定義と完全一致するかを毎回検証する（不一致なら `ng`）。
   * 乖離ノード数（21 / 248）および最大乖離（K1-05: 表示 0.707 vs 再計算 0.233）等は
     `src/verify_doc.py` の照合対象として監視する。

---

## 3. この判断の取り消し条件

次のいずれかが必要になった場合は、v17 原本を書き換えるのではなく、
**新規の可視化生成系（v18 以降の独立ビューア）** として別枝を事前登録したうえで構築する。

* v17 インタラクティブ HTML 自体を外部公開・一般配布する計画が生じた場合。
* 単層ベース（表示エッジのみから再計算した被説明率）を独立の主張または教育用図版として用いる場合。

---

## 4. 追記（2026-11-28）: 被説明率の再計算不能性を列として固定する

### 4.1 何が再計算できないのか

v17 HTML のノードには「表示被説明率」が埋め込まれている。この値は**単層の重み付き入次数から
再計算できるものではない**。理由は 3 つで、いずれも `derived/` の台帳に列として残した。

| # | 理由 | 実体 | 影響するノード |
| ---: | :--- | :--- | ---: |
| R1 | 表示エッジ 597 本のうち 126 本が**古事記への流入辺**で、重みが L1 コサインと一致しない（剥離 2 段目以降・変換重み・L2 合成の寄与） | `outputs/edge_reproduction.csv`（`l1_mismatch` 221 本のうち 71 本が古事記流入） | 37 |
| R2 | 古事記 37 話の表示値は v16 の 3 層分解（`decomp.total_final`）に由来し、**層構成が HTML に含まれない** | `derived/html_embedded_v17_audit.json` の `provenance` | 37 |
| R3 | L2 優位の 16 ノードは 90 次元ベクトルを HTML から復元できず、`pureL2_dom` として分母から外れる | 同上 | 16 |

### 4.2 機械出力（新規）

`src/display_reproducibility.py` が全 297 ノードを 1 行ずつ判定し、次を出力する。

* `derived/display_reproducibility.json`（git 管理下）: 全体・`kind` 別・出所別の内訳、
  再計算可否の集合、乖離 21 件のノード ID。
* `outputs/display_reproducibility.csv`（git 対象外）: 1 行 1 ノードの作業台帳。

| 区分 | ノード数 | 再計算可 | 不可 | 0.01 超の乖離 |
| :--- | ---: | ---: | ---: | ---: |
| 全体 | 297 | 248 | 49 | 21 |
| 古事記（`decomp.total_final`） | 37 | 36 | 1 | **21** |
| ユーラシア（`v16.L1`） | 244 | 212 | 32 | 0 |
| アンカー（`pureL2_dom`） | 16 | 0 | 16 | 0 |

### 4.3 既存検査との突き合わせ

`src/verify_network.py` の F10（乖離 21 / 評価可能 248）と、本台帳の `cross_check` は
**集合として一致**する（`gap_matches_expected` / `evaluable_matches_expected` がいずれも true）。
乖離はすべて古事記ノードに集中し、ユーラシア 244 ノードには 1 件も無い。
これは「表示混成の影響が古事記側の表示値に閉じている」ことの機械的な証拠であり、
ADR 0003 §1 の判断 B（凍結 HTML を維持し、注記＋台帳で運用する）を支持する。

### 4.4 取り消し条件の追加

R1〜R3 のいずれかが解消された場合（例: v18 以降で層別の重みを HTML に同梱する新ビューアを作る場合）は、
本節の表を更新するのではなく、**新しいADRを起こして台帳のスキーマを版上げする**。
台帳の数値を遡って書き換えてはならない（`derived/` は追記型で運用する）。
